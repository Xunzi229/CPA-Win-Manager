# CPA 统一管理器

用于在 Windows 上统一管理 [CLIProxyAPI](https://github.com/router-for-me/CLIProxyAPI) 和 [CPA-Manager-Plus](https://github.com/seakee/CPA-Manager-Plus)。两个项目分别安装、更新和控制服务，共用代理设置。

## 功能

- 根据 Windows 系统架构下载并校验两个项目的 amd64 或 ARM64 版本；更新时保留原有配置和数据。
- 查看本地与最新版本，启动、停止或重启各自的服务。
- 自动检查更新，并在有新版本时显示提示。
- 保存项目目录和公共代理设置；支持查看与保存 CPA-Manager-Plus 登录 Key。
- 显示管理器自身版本，启动后自动检查更新，也可手动检查；使用公共代理下载对应架构的发布包，校验 SHA256 后自动重启更新，不修改设置或停止两个项目的服务。

管理器自身的“检查更新”“更新管理器”和“发布页面”入口位于顶部“设置”窗口中。源码运行时，更新按钮打开发布页面，不覆盖源码。更新暂存文件和旧版备份保存在 EXE 同目录的 .manager-update-* 文件夹；替换失败时尝试恢复旧版，错误记录为该文件夹下的 update-error.log。请确保 EXE 所在目录可写。

## 使用

双击两个软件列表中的 GitHub 地址单元格可直接修改地址，回车保存、Esc 取消；地址校验或仓库去重失败时保留原记录。更换仓库后需手动检查获取新源的附件，安装器历史下载包仍可清理。

便携软件和安装器软件列表均将包大小单独显示为一列，附件下拉框只显示文件名。右键软件行可检查更新、安装、打开目录、复制地址、查看发布页面或移除记录；安装器行还可重命名和清空下载包，便携软件行可选择最新版本。

两个软件列表的表头和列数据均居中显示。便携软件获取成功后的版本与附件数据独立缓存到 `.release-cache/`（旧配置缓存自动迁移），切换软件或重启管理器时直接复用；手动“检查 / 获取附件”或右键检查更新会刷新缓存。修改 GitHub 地址后清除该软件的旧缓存。点击列表行或单元格只切换当前软件与本地选项，没有缓存时需手动获取，不自动请求版本信息。

### 通用 GitHub 软件安装

#### 安装器软件列表

“安装器软件”页独立管理 EXE/MSI 安装器：输入 GitHub 地址后添加并获取最新附件，同一仓库地址只保留一行（主页和 Releases 地址、大小写差异会统一识别）。已有的有效安装器配置自动迁移到列表。每行显示软件名称、地址、所选附件及大小、已下载版本、最新版本和状态；双击名称可以自定义软件名称，直接点击该行的“对应包”单元格切换附件。

- “检查此行”和“检查全部”只查询发布版本，不下载；“下载待更新”先检查全部，再只下载没有相应本地包的软件，不批量打开向导。
- “安装”下载或复用所选包并自动打开安装向导；“更新”先检查最新版本，再下载或复用并打开向导。记录版本、附件和文件标识一致且本地文件校验通过时不重复下载，切换附件或文件损坏时重新下载。
- 下载目录由“设置”统一管理，包按仓库保存到 `installers-*` 子目录中。已下载版本是安装包版本，不能代表软件是否完成安装。
- “清空此行下载包”和“清空全部下载包”删除已记录的安装器文件及附件缓存，保留软件记录和已安装的软件。删除失败的记录保留用于重试；移除软件记录前需先清空下载包，避免留下无法管理的历史文件。

#### 便携软件

列表展示软件安装目录、GitHub 地址、本地版本、最新版本、选择安装版本和对应包。点击行内带 ▾ 的版本或附件单元格可直接选择；首次获取默认选择最新正式版本，并按本机架构推荐附件。可选择最近 100 条发布记录中的历史版本（含预发布），切换安装版本不会改变“最新版本”列。已选版本与附件随软件配置保存；本地版本来自管理器的安装记录。

在“便携软件”页点击“解压安装根目录”并选择安装目录。便携软件列表显示安装目录；同一根目录可以重复添加并建立独立软件记录，GitHub 软件源按仓库唯一（大小写、.git 和 Releases 地址差异统一识别）。同目录中的本地版本记录按仓库分别保存。填写公开 GitHub 仓库或 Releases 地址，点击“检查 / 获取附件”，选择与 Windows 架构对应的发布附件。点击软件行时复用缓存，不自动获取版本与附件；需要刷新时手动检查。EXE/MSI 安装器使用独立的“安装器软件”页管理。

- **便携安装**：支持 ZIP 和单个 EXE。ZIP 仅有一层或多层外包装目录时自动去除包装；替换同名文件，不删除其他已有文件。安装前请关闭目标软件。
- 便携安装直接使用已选软件目录，不再显示额外的安装目录输入框和选择按钮。顶部“设置”统一配置代理和安装器下载目录，所有安装器软件共用；默认使用 Windows 当前用户的系统“下载”目录（支持系统目录重定向），清空目录设置后保存也会恢复系统默认值。已有自定义目录继续保留，旧配置首次迁移时沿用第一个安装器软件的下载目录。此设置独立保存，不再按软件配置。
- **附件选择**：附件列表同步显示文件大小，并按当前 Windows 原生架构自动选择推荐附件，支持 amd64/x64/64、arm64/aarch64、x86/86/32 等命名。便携模式优先对应架构的 ZIP，安装器模式优先对应架构的安装器；仍可手动切换。只有其他系统或明确不兼容架构时不自动选中。
- **下载与暂停**：根据文件大小使用最多 4 个线程分段下载，显示已下载大小、总大小和速度。下载时进度条右侧显示 `⏸`，点击暂停后显示 `▶`，点击继续恢复当前下载。切换软件或附件时停止旧下载，清空进度、日志和暂停状态，旧任务结果不会覆盖新选择。缓存位于管理器目录的 `.download-cache`，支持分段的附件再次下载时可续传（包括重启管理器后）。服务器不支持分段时退回单线程，停止任务后需重新下载。文件标识或服务器校验标识变化时重新下载；下载完成进入安装阶段后隐藏暂停图标。点击“取消任务”停止下载并保留断点；关闭窗口时会停止下载，若正在写入安装文件则等待完成后退出。批量任务取消后不再处理后续软件，也不会自动打开安装向导。
- **额外保留文件 / 目录**：默认留空。安装仅覆盖包内存在的同名文件，其他已有文件不覆盖、不删除。需要额外保护的包内同名文件可填写相对路径，以分号分隔，例如 `config.yaml;data`；已有内容不会被覆盖，缺失的默认文件仍可新增。已保存的保留路径继续生效，可自行清空。
- GitHub 附件提供 SHA256 或标准校验文件时验证下载；没有可识别校验值时在日志中说明。安装记录用于显示由本管理器安装的版本，不执行陌生软件探测版本。
- 便携安装备份保存在安装目录的 `.install-backup-*` 中，替换失败会恢复已修改文件。软件配置存于 `manager-settings.json`，移除记录不会删除安装文件。多个软件可共用安装根目录；安装仍会覆盖包内同名文件，请按软件实际文件布局选择目录。

暂不支持源码构建、RAR/7z/tar 包、私有仓库和无人值守安装；GitHub API 限流或没有正式 Release 时会显示错误。

1. 从 [Releases](https://github.com/Xunzi229/CPA-Win-Manager/releases/latest) 下载与 Windows 架构对应的 amd64 或 ARM64 压缩包，解压后运行 `CPA-Unified-Manager.exe`。
2. 在对应页面选择项目目录，点击“安装最新版”，然后启动服务。
3. 使用 CLIProxyAPI 前，在安装目录的 `config.yaml` 中配置上游账号。

首次安装默认仅监听本机：CLIProxyAPI 使用端口 8317，CPA-Manager-Plus 使用端口 18317。程序配置保存在 EXE 同目录的 `manager-settings.json`。

每次推送 `v*` 标签时，GitHub Actions 会分别构建 Windows amd64 和 ARM64 安装包并发布 Release。

## 从源码构建

源码按公共基础能力、后端、界面页面和可复用控件分层，测试统一位于 `tests/`。目录职责和开发约定见 [项目结构说明](docs/architecture.md)。源码入口仍为 `python manager.py`，现有配置与缓存位置保持不变。

需要 Windows、Python 3.10+ 和 PowerShell。在仓库根目录运行：

```powershell
powershell -ExecutionPolicy Bypass -File .\build.ps1
```

生成的 `CPA-Unified-Manager.exe` 位于仓库根目录。运行源码前先安装依赖：

```powershell
python -m pip install -r requirements.txt
python manager.py
```

运行回归测试使用 `python -m unittest discover -q`。需要独立构建目录时使用 `.\build.ps1 -OutputDirectory .build\preview`，普通分支 push 和 PR 会自动运行 Windows amd64 / ARM64 构建与测试，标签发布继续使用独立 Release 工作流。
